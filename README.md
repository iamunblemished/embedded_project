# Sim-to-Real Edge AI System for Non-Intrusive MCSA

## Overview

This repository contains the embedded software components for a **Sim-to-Real Edge AI System** designed for **Non-Intrusive Motor Current Signature Analysis (MCSA)**. Developed as part of the Embedded Project lab at Hochschule Ravensburg-Weingarten University (under the guidance of Prof. Dr. Christoph Ellenrieder), the system provides real-time predictive maintenance for induction motors.

By utilizing a current transformer at the breaker box, the system non-intrusively monitors the motor's electrical draw. It employs a Hardware-in-the-Loop (HIL) approach, ingesting synthetic data generated by a MATLAB/Simulink Digital Twin, extracting frequency features on an edge DSP node, and pushing anomaly alerts to the cloud via a wireless telemetry coprocessor.

---

## System Architecture

The project is split into two primary Zephyr RTOS applications running on separate microcontrollers:

### 1. Compute Brain (NXP LPC55S69)

* **Ingestion:** Captures 1024-byte payloads of synthetic motor current data over a hardware UART interrupt directly from Simulink.
* **Signal Conditioning:** Removes the DC offset and applies a pre-computed Hann window to prevent spectral leakage from masking tight fault sidebands.
* **DSP:** Executes the **Goertzel Algorithm** to extract the specific magnitudes of the fundamental carrier wave (50Hz) and slip-dependent fault sidebands (e.g., 75Hz).
* **Evaluation:** Calculates a relative severity metric in decibels (dB) to prevent load variations from masking the result, then formats the data into a JSON payload.
* **Handoff:** Transmits the JSON payload to the telemetry node via a secondary UART (`flexcomm2`).

### 2. Telemetry Coprocessor (ESP32)

* **Non-Blocking Reception:** Catches the incoming JSON strings from the NXP board using a silent UART Interrupt Service Routine (ISR) to prevent CPU starvation during network operations.
* **Thread Safety:** Passes data safely from the ISR to the main thread using Zephyr message queues (`K_MSGQ`).
* **Connectivity:** Manages the networking stack and secures a WPA2 Wi-Fi connection.
* **Cloud Publishing:** Resolves DNS and connects to a cloud MQTT broker (`broker.emqx.io` on port 1883), publishing the telemetry data to the `mcsa/telemetry/node_1` topic for dashboard monitoring.

## Dependencies and Prerequisites

* **RTOS:** Zephyr RTOS (v3.x or compatible)
* **Hardware:**
* NXP LPC55S69 Development Board
* ESP32 Development Board


* **Simulation Environment:** MATLAB/Simulink for generating the baseline and fault current signatures over a serial bridge (e.g., `/dev/ttyACM0`).
* **Networking:** A 2.4GHz Wi-Fi network and access to an MQTT broker.

## Mathematical Foundation

The DSP node relies on the **Hann window** for signal conditioning to ensure the massive 50Hz fundamental peak does not bleed into the micro-signals of the fault sidebands:


$$w[i] = 0.5 \left( 1 - \cos\left( \frac{2\pi i}{N-1} \right) \right)$$

Frequency magnitudes are isolated using the **Goertzel Algorithm**, which acts as a targeted magnifying glass, avoiding the heavy computational overhead and rigid grid locking of a full FFT:


$$M = \sqrt{q_1^2 + q_2^2 - q_1 q_2 \cdot \text{coeff}}$$


*(Where $\text{coeff} = 2\cos\left(\frac{2\pi k}{N}\right)$)*
